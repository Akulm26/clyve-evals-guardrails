How to read this

Every metric has
  • A formula built from named counts
  • A table saying where each count comes from
  • Steps to collect it
  • A worked example with illustrative numbers
  • A stamp saying how sure the number is
Source tags
  • PUBLIC counted from public pages, no client access
  • RUNS counted from the AI prompt run log
  • FOUNDER comes from the founder call
  • CLIENT needs data the client shares
  • PLATFORM a platform's own analytics (LinkedIn, Instagram, Gumroad, sending tools)
  • CLYVE Clyve's own logs and records
Revenue link
  • Direct the number is money, or the step before it
  • Indirect a plausible cause of a direct number
  • Weak a thin link; not for headlines
  • None a prerequisite or a gate
Stamps (framework)
  • Observed counted from a public source
  • Assumed ±1 public-only, before the founder call
  • Captured after the founder call
  • Our read Akul's interpretation only
Provisional

Formulas are working definitions drafted from the ContentOS framework rules. The framework fixes what each track measures and how it is sampled; the exact arithmetic here is proposed wording. Freeze the definitions at Day 0 of each engagement. Worked examples use made-up numbers for a hypothetical D2C brand and are not results.

Rules that protect the numbers

Freeze the prompt set and definitions at Day 0. Split every figure by query type. Run client baselines in the real app interfaces and screenshot every run; an API trend track may run alongside but is labelled separately and never mixed in. A change counts only if it beats both the noise band and the chance band (see O2), and is reported as a figure only if it clears the smallest provable move (see C5).
